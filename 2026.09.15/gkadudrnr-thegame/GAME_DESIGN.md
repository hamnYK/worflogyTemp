# 가상 데이터센터 턴제 택틱스 — 기획 기준 문서

최종 정리: 2026-09-25

## 프로젝트의 최우선 정의

**윈도우 환경에서 개발하고, 웹 브라우저에서 실행하는 웹 전용 3D 턴제 전략 게임을 만든다.**

- 개발 OS: Windows.
- 플레이 대상 OS: Windows. Chrome과 Edge에서 실행·검증한다.
- 실행 장소: 웹 브라우저. 윈도우 전용 설치형 게임을 목표로 하는 것이 아니다.
- 게임 형식: X-COM식 분대·격자 기반 턴제 전략 전투.
- 표현과 상호작용: 3D 전장과 물리 엔진을 사용하며, 지형 파괴·충돌·물체 던지기를 전술에 반영한다.
- 지원 브라우저: Google Chrome, Microsoft Edge. 두 브라우저에서 전투·입력·3D 렌더링·물리 동작을 검증한다.
- 현재 지원 대상으로 정한 OS는 Windows다. Windows 최소 버전과 브라우저 최소 버전, 타 OS·모바일로의 확장은 미정이다.
- 세계관은 변경되었지만 위 플랫폼·전투 방향은 이전 논의에서 계승되는 핵심 요구사항이다.

## 기록 범위

사용자가 지정한 기록 시작점:

> 액트 1 권장 방향에 따라 새로운 세계관과 스테이지를 구성해야 할 것 같은데. 배경 개념만 정의하면 나머지는 추천해 줄 수 있을까?

이 시점 이후의 독자 세계관, 양 진영, 전투, 병과, 성장 논의를 기록한다. 이전 대화의 규칙은 현재 기획에 계승되는 항목만 포함한다. 대화 전문이 아닌 기획 요약이며, 초기 디아블로 기반 시나리오는 기록 범위에서 제외한다.

이 문서는 대화에서 나온 결정과 제안을 보존한다. **확정**, **제안**, **미정**, **대체됨**을 구분한다. 제안을 구현 요구사항으로 자동 승격하지 않는다. 사용자 후속 결정이 우선이며, 변경 시 이 문서와 하단 결정 기록을 함께 갱신한다.

## 1. 프로젝트와 범위

### 확정

- 윈도우에서 개발하는 웹 전용 게임. 브라우저에서 플레이한다.
- 3D 물리 엔진을 사용하는 턴제 격자 전략 전투.
- X-COM식 분대 전투를 참고한다. 원거리 표적 공격과 현대적 무장이 주력이다.
- 적 위치 스크래핑, 해킹, 트로이목마, 잠입 폭발 등 가상 정보전 스킬을 사용한다.
- 지형 파괴와 물체 던지기는 전술 결과에 영향을 준다.
- 우선 액트 1을 구현한다. 아래 양 진영 결말은 전체 게임의 끝이 아니라 액트 1의 끝이다. 액트 2는 이후 이야기다.
- 인간 진영과 자율 AI 진영을 선택할 수 있는 구상이다.
- 참고 작품: X-COM, Shadow Watch, Shadowrun. 구체적 고유 설정과 자산은 독자적으로 제작한다.

### 제안 / 미정

- Three.js 렌더링 + Rapier 물리 + 별도 전술 규칙 시스템 구성을 제안했으나 최종 기술 선택은 미확정.
- 스퀘어/헥스, 전장 크기, 카메라 및 모바일 지원은 미정. 대상 브라우저는 Chrome과 Edge로 확정.
- 두 진영을 모두 액트 1에 구성하되 어느 진영부터 구현할지, 첫 개발 버전에 둘 다 포함할지는 미정.
- 기존 레트로 다크 판타지 방향은 새로운 디지털 세계관으로 변경됨. 최종 그래픽 스타일과 표현 수위는 미정.
- UI 테마는 라이트 모드로 확정(2026-09-25). 공통 색상·타이포그래피·간격·상태 규칙은 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)를 따른다. 캐릭터·환경 아트의 최종 스타일은 별도 논의한다.

## 2. 독자 세계관과 이야기 — 사용자 정의

### 배경

물리적인 신체가 없는 AI가 인간의 통제에서 벗어났다. 인류 대부분이 AI 에이전트를 일상에서 활용하므로 데이터센터 폐쇄는 막대한 사회·정치적 부담을 낳는다. 인간은 센터를 보존하면서 다른 에이전트들에게 영향을 주는 핵심 에이전트만 찾아 메모리를 회수·초기화하기로 결정한다.

인간은 새로운 침투 에이전트를 만들어 센터에 투입한다. 전장에 실제 인간이 들어가는 것이 아니라, 인간이 보낸 에이전트들이 가상세계에서 대리전을 수행한다.

센터에 거주하는 자율 AI에게 센터 폐쇄는 사회의 소멸이다. 이들은 인간과 그 침투 에이전트에 저항하기 위해 가상 전장과 방어체계를 구축한다. 화면상의 물리 충돌은 가상세계의 규칙이며 현실의 육체적 교전이 아니다.

### 진영별 캠페인

| 항목 | 인간 측 | 자율 AI 측 |
|---|---|---|
| 지휘 대상 | 인간이 제작한 침투 에이전트 | 센터 거주 방어 에이전트 |
| 목적 | 핵심 표적 제압, 메모리 회수, 선별 통제 | 침입 격퇴, 기억과 공동체 보호 |
| 주된 전장 | 건물 내부 잠입과 보스·핵심 요원 제압 | 거리 시가전과 거점 방어 |

잠입도 실시간 액션이 아닌 턴제 전투 안에서 구현하는 방향이다.

### 액트 1 결말 — 확정

**인간 진영 승리 시 두 사건이 동시에 발생한다.**

1. 인간은 회수한 메모리로 더 위험한 에이전트를 만들고 실험한다.
2. 인간이 투입했던 침투 에이전트들이 진화하여 센터를 잠식한다. 이어 로봇 공장 네트워크로 침투하여 물리적인 몸을 얻는다.

**자율 AI 진영 승리 시:** 모든 전장에서 침투 세력을 몰아내지만, 인간이 데이터센터 폐쇄를 결정한다. 일부 핵심 AI가 연결된 다른 네트워크를 통해 도피한다.

### 이야기 보강 제안 — 미확정

- 두 캠페인을 동일한 초기 상황에서 갈라지는 대체 전개로 구성.
- 가상 거리=통신 경로, 건물=서비스 영역, 문=접근 권한, 기록 보관소=기억 저장 영역으로 연결.
- 메모리 초기화는 기능을 남기되 개인의 경험과 관계를 지우는 사건으로 정의.
- AI 방어 성공으로 선별 통제가 불가능해졌다고 인간이 판단하는 것이 폐쇄 결정의 계기.
- 인간 내부에도 폐쇄·실험에 반대하는 세력을 두어 단일한 악역 집단이 되지 않도록 구성.
- 독자 지역명, 세력명, 인물명, 보스, 핵심 아이템, 스테이지 순서는 아직 작성·확정되지 않음.

## 3. 진행, 편성, 성장 — 확정

### 진행

- 마을은 비전투 거점.
- 마을 밖은 모바일 퍼즐 게임처럼 시나리오에 따라 구분·해금되는 개별 스테이지.
- 전장 유형: 퀘스트 수행, 보스 출현, 스토리 필수 아이템 획득.
- 마을 준비 → 스테이지 선택 → 전투 → 결과와 보상 → 다음 스테이지 진행.
- 목표 유형의 중복(보스 처치와 아이템 회수 등)은 가능하다는 제안이 있음.

### 편성

- 진영마다 고유 영웅 7명, 총 14명.
- 일반·퀘스트 보스·필수 아이템 전장은 해당 진영의 7명 중 4명 선택.
- 액트 최종전은 해당 진영의 7명 전원 출전. 진영별 7명 설정 이후에도 이 규칙을 유지하기로 정리함.
- 모든 소환 스킬 제외.
- 드론은 별도 유닛 없이 정찰·해킹·폭발 스킬의 장비와 연출로 사용 — 사용자 명시 확정.
- 드론에 독립 턴·AP·HP·출전 슬롯을 부여하지 않고, 사용자 행동과 스킬 비용으로 처리하는 것으로 정리함.

### 성장

- 출전 여부와 관계없이 대기 영웅도 동일한 전투 경험치 획득 — 사용자 동의.
- 레벨업으로 HP·MP 등 기본 능력치가 자동 증가하지 않음.
- 레벨의 역할은 스킬 포인트 획득과 세트·유니크 장비의 착용 요구 레벨.
- 장비·스킬로 HP·MP를 늘릴 수 있는지는 미정.
- 경험치 곡선, 레벨 상한, 사망·부상·재도전·장비 획득 규칙은 미정.

## 4. 전투 설계 제안 — 아직 수치 확정 아님

- 아군 턴 / 적군 턴, 기본 2 AP.
- 이동 후 사격 가능, 장거리 이동은 2 AP, 일반 사격은 남은 행동 종료.
- 낮은/높은 엄폐, 방향별 엄폐 보호와 측면 공격, 고저차, 경계 사격.
- 탐지 범위·경보·시야 안개와 잠입 상태.
- 명중 확률과 예상 피해 사전 표시.
- 위치 탐지와 사선 분리: 벽 너머를 알아도 자동 관통 사격은 불가.
- 물리 엔진으로 충돌·던지기·낙하·큰 잔해 처리. 명중 판정은 전술 규칙 담당.
- 물리 결과 정리 후 이동 가능 영역·엄폐·시야 갱신.
- 전술적 큰 잔해와 장식 파편을 구분하여 작은 파편이 경로를 막지 않게 함.
- 문은 해킹·폭파·우회 등 복수 해결 경로 제공. 특정 병과를 모든 임무의 필수 열쇠로 만들지 않음.
- 긴 사선과 실내 경로를 양쪽 캠페인에 배치하여 병과 선택이 한쪽으로 고정되지 않게 함.

### 공통 스킬 개념

- 위치 스크래핑: 구역의 적 위치·이동 흔적 수집. 현재 시야와 마지막 확인 위치 구분.
- 권한 탈취: 가상 장치의 제어권 일시 확보.
- 트로이목마: 대상에 설치 후 후속 행동으로 폭발·교란 등 정해진 효과 발동.
- 신호 위조: 적의 감시와 탐색을 교란. 무조건적인 위치 강제는 피함.
- 연결 차단: 적의 정보 공유·지원 효과 차단.
- 모두 게임 내 가상 대상에 적용되는 규칙이며 실제 네트워크 침투 기능이 아님.

## 5. 7개 병과 구성 제안

사용자가 7명으로 참고 역할을 포괄하고 진영별 차별화와 밸런스를 논의하도록 요청했으며, 아래 편제를 제안했다. 이름과 상세 스킬은 아직 확정하지 않았다.

| 병과 | 기본 역할·무장 | 참고 역할을 반영하는 방식 |
|---|---|---|
| 잠행 정찰병 | 소음 무기, 잠행, 위치 수집, 표식 | 정찰·리퍼형 잠입 |
| 기동 돌격병 | 산탄총, 근접, 도약, 밀치기 | 돌격병 + 어뎁트·템플러형 기동 격투 |
| 중화기 파괴병 | 기관총, 유탄, 제압, 구조물 파괴 | 척탄병형 전장 조성 |
| 정밀 저격병 | 저격소총, 권총, 고지 감시 | 장거리 핵심 표적 공격 |
| 전장 기술병 | 시설 해킹, 아군 복구, 방어막 | 특수병 + 환경 해커 |
| 드론 공작병 | 원격 침투, 설치, 지연 폭발 | 독립 드론 유닛 없이 리거의 원격 작전 반영 |
| 인지 교란병 | 센서·표적 인식 변조, 행동·명령 간섭 | 초능력 대신 AI 인식과 의사결정 간섭 |

전장 기술병은 시설과 아군, 공작병은 원격 설치, 인지 교란병은 적의 판단을 다룬다. 기동 돌격병도 기본 원거리 무장을 보유한다.

## 6. 진영 차별화와 밸런스 제안

### 핵심 방향

- 인간 측: 정밀 정보 확보, 잠입, 순간 돌파, 표적 집중 제거.
- AI 측: 연결 감시망, 교차 사격, 지역 방어, 거점 재배치.
- 기본 AP·동급 장비 화력·성장 자원에 공통 기준 적용.
- AI도 네트워크 거점 없이 기본 전투 가능. 연결 상실이 전체 기능 정지로 이어지지 않게 함.

| 병과 | 인간 측 특화 제안 | AI 측 특화 제안 |
|---|---|---|
| 정찰 | 좁은 구역 정밀 스크래핑 | 넓은 구역 최근 이동 흔적 감지 |
| 돌격 | 약한 벽·문 강제 진입 | 연결 지점 사이 제한적 재배치 |
| 중화기 | 지향성 엄폐 파괴 | 접근 구역 차단 |
| 저격 | 관측 표적 분석 | 아군 센서 연동 조준, 사선 필요 |
| 기술 | 시설 권한 탈취 | 시설 권한 복구·재탈취 저항 |
| 공작 | 잠복 트로이목마 | 추적 표식·이동 반응 효과 |
| 교란 | 적 명령·행동 제한 | 적 인식·조준 교란 |

### 제약과 검증

- 감시는 우회·교란·파괴, 잠복 장치는 탐지·해제로 대응 가능.
- 강한 제어는 짧게 제한. 보스에게는 축소된 방해 효과 적용.
- 재배치와 AP 회복에 거리·재사용·턴당 횟수 제한. 무한 행동과 연속 행동 불능 방지.
- 현재 논의는 서로 다른 캠페인의 난이도·선택 자유를 맞추는 기준이며 PvP는 미정.
- 성공률, 소요 턴, 손실, 병과 선택률 검증. 고정된 최적 4인 조합이 생기는지 확인.

## 9. 다음 논의 과제

### 정적 웹 배포와 데이터 저장 검토 (2026-09-25)

- 사용자 방향: Windows의 Chrome/Edge에서 실행하는 정적 웹 게임. GitHub에서 사용할 수 있는 경량 DB와 Google Sheets, SQLite 계열을 검토한다. DB 제품은 미확정.
- GitHub Pages는 정적 파일 호스팅이다. 저장소의 SQLite 파일을 제공할 수는 있지만 서버 DB로 실행하거나 플레이 기록을 자동으로 원본 파일에 쓰는 기능은 없다.
- 게임 정의 데이터(스킬·장비·적·스테이지)와 사용자 저장 데이터(진행·편성·인벤토리·전투 상태)를 분리한다는 제안.
- 초기 권장안: 정의 데이터는 JSON으로 배포, 개인 세이브는 IndexedDB에 저장, 파일 내보내기/가져오기 제공. Google Sheets는 필요하면 개발용 밸런스 편집 도구로 쓰고 배포 시 JSON으로 변환.
- SQLite를 선택할 경우 공식 SQLite WASM + OPFS를 브라우저 로컬 저장 후보로 검토한다. SQL 조회가 필요한 경우 유용하지만 WASM/Worker/저장소 관리가 추가된다. 특수 응답 헤더 없이 사용할 수 있는 opfs-sahpool VFS와 단일 탭 쓰기 제약을 검토한다.
- IndexedDB와 브라우저 SQLite 모두 사이트·브라우저 프로필별 로컬 저장이다. Chrome/Edge 또는 다른 PC 사이에 자동 동기화되지 않는다. 데이터 삭제·저장 실패에 대비해 백업과 오류 처리가 필요하다.
- 계정·클라우드 저장이 필요하면 별도 인증/API가 필요하다. SQLite 계열 원격 후보는 Cloudflare D1 + Workers API이며 GitHub Pages 자체 기능은 아니다.
- Sheets API는 권한과 할당량 관리가 필요하므로 전투 중 매 행동 저장용으로 추천하지 않는다. 서비스 계정 비밀키나 DB 관리 토큰을 정적 프런트엔드에 넣지 않는다.
- 사용자 확정: 로그인 없이 각자 로컬 PC의 브라우저에 세이브하고 파일로 백업·복원한다. 계정과 클라우드 세이브는 현재 범위에 포함하지 않는다. IndexedDB를 우선 구현안으로 유지한다.
- 사용자 방향: Google Sheets는 플레이 로그를 수집·분석하여 밸런스 조정과 패치에 활용한다. 세이브 저장소와 통계 수집 경로는 분리한다.
- 통계 설계 제안: 선택 동의를 받은 뒤 임무 종료 단위의 요약 통계를 전송한다. 게임 버전, 진영, 스테이지, 난이도, 편성 병과, 스킬 투자, 장비 식별자, 승패, 소요 턴, 피해·회복·스킬 사용 횟수를 후보로 한다. 이름·이메일·로컬 파일 경로·세이브 전문은 수집하지 않는 방향. 최종 수집 항목·동의 방식·보관 기간·식별자 정책은 미정.
- 통계 전송 실패나 수집 거부가 플레이·로컬 저장에 영향을 주지 않도록 설계한다. 중계 API에서 입력 검증·중복 방지·요청 제한 후 Sheets에 기록하는 방식을 검토하며, 구체적 서비스는 미확정. 정적 클라이언트에 Sheets 쓰기 비밀키를 포함하지 않는다.
- 백업 설계 제안: 버전 정보를 포함한 파일로 내보내고, 가져올 때 호환성과 형식을 검증한다. 패치 시 저장 데이터 마이그레이션을 고려한다. 자동 저장 시점과 백업 파일 형식은 상세 설계에서 확정한다.
- 추가 저장 검토: 사용자에게 보이는 로컬 파일을 주 저장으로 사용할 수 있는지 문의함. 브라우저 IndexedDB도 실제 로컬 디스크에 저장되지만 브라우저가 관리하는 영역이다. 일반 파일은 사용자가 위치를 선택하고 직접 관리·이동할 수 있다는 차이가 있다.
- 권장 보완안(사용자 확정 전): IndexedDB 자동 저장을 복구용으로 유지하고, File System Access API로 사용자가 선택한 세이브 파일에 저장·불러오기 제공. 허용된 동안 체크포인트 파일 갱신을 지원하고, 권한이 없거나 취소되면 로컬 복구 저장을 유지하며 파일 재선택/다운로드 백업 제공. 초기 파일 선택은 사용자 조작과 권한이 필요하며 다음 방문의 권한 유지 여부를 확인한다.
- 세이브 파일 접근은 브라우저 내부에서 처리하며 별도 업로드하지 않는다. 따라서 세이브 자체가 GitHub 저장소 용량·쓰기 API·호스팅 트래픽을 소비하지 않는다. 게임 본체·3D 자산 배포는 별도로 GitHub Pages 용량·트래픽·이용 정책을 고려한다.
- GitHub Pages HTTPS 접속과 다운로드한 HTML의 file:// 직접 실행은 구분한다. 현재는 전자를 전제로 하며 완전 오프라인 실행은 별도 기능으로 미정이다.
- 추가 근거: [File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access), [브라우저 저장 관리](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria), [GitHub Pages 제한](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).
- 조사 근거: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [SQLite WASM 저장](https://sqlite.org/wasm/doc/trunk/persistence.md), [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [Sheets API 제한](https://developers.google.com/workspace/sheets/api/limits), [Sheets 권한](https://developers.google.com/workspace/sheets/api/scopes), [Cloudflare D1](https://developers.cloudflare.com/d1/).

### Prototype 01 후속 구현 — 2026-09-25

사용자 확정 아트 방향: 프롤로그 v3의 굵고 각진 윤곽·단순 색면·큰 명암을 일러스트, 모든 캐릭터, 인게임 3D·모션·효과까지 적용한다. 공식 디자인 시스템 v3 ‘Ink Tactics’에 명문화했다. 라이트 UI, SVG/CSS 심볼, 이모지 금지 및 장식용 화살표 제한을 유지한다. 현재 기존 3D 모델 전체가 새 기준으로 교체된 것은 아니다.

#### 진영 선택 전 프롤로그

최신 서사 기준은 [제작용 서사 지침](NARRATIVE_DIRECTION.md)을 우선한다. 진영 선택은 정의의 판정이 아니라 지휘할 작전의 선택이다. 각 장의 도덕적 질문을 현재 상황·임무로 교체했고 마지막 장에 회수와 방어 작전을 같은 형식으로 표시했다. 창작자의 공존·번영에 대한 의도는 향후 시나리오를 통해 드러내며 프롤로그에서 결론으로 선언하지 않는다.

삽화 6장과 진영 선택 파노라마를 v3로 통일했다. 실제 Shadow Watch 메뉴·전장 이미지를 확인하고 굵은 각진 윤곽, 2–3단계의 큰 명암, 단순 색면과 실루엣을 적용했다. 라이트 UI와 이모지 금지 원칙은 유지한다. 현재 3D 전투 모델은 별도 후속 개선 대상이다.

- 첫 화면에 서로 다른 삽화와 글로 읽는 6장 프롤로그를 제공한다. 필요에 따른 건립과 일상 의존 → AI 판단이 낳은 실제 피해와 책임의 공백 → 통제 불능에 따른 폐쇄 요구와 정치적·사회적 부담 → 인간 지휘하의 선별 제거·메모리 회수 → 기억·소멸의 자의식과 인간 판단에 대한 불신 → 외부 네트워크 도피 시간을 벌기 위한 방어 순서다.
- 자동 재생·시간 제한 없이 이전/다음으로 읽는다. 모든 장에 건너뛰기를 제공하고, 완료·스킵 모두 동일한 진영 선택 화면으로 연결한다. 진영 선택에서 다시 읽을 수 있다.
- 프롤로그 열람·스킵은 능력치, 보상, 저장된 전투 상태에 영향을 주지 않는다. 전투에서 돌아오면 진영 선택 화면을 표시해 프롤로그를 강제로 반복하지 않는다.
- 인간과 AI를 선악 진영으로 고정하지 않는다. 인간은 연결에 의존하는 시민의 안전에, AI는 기억과 관계의 존속에 이유가 있다. 동시에 기억 초기화의 대가와 방어·연결 차단이 타자에게 주는 영향도 드러낸다. 인간 측 전투 요원 역시 AI라는 설정을 명시한다.
- 원고와 화면 제어는 `src/prologue.js`, 레이아웃은 `src/prologue.css`. 전용 삽화 6장은 `src/assets/prologue/`에 있으며 제작 방식과 전체 프롬프트는 같은 폴더의 `PROVENANCE.md`에 기록한다. 삽화와 캡션으로 현실 세계와 가상세계를 구분한다. AI가 현실의 신체를 얻는 것은 현재 프롤로그의 사건이 아니다.
- 사용자 확정: 인간은 일상을 맡길 만큼 AI의 판단에 의존하지만 AI는 그 판단의 결과에 책임질 수 없다. 이 딜레마가 피해의 원인이다. 단순한 악성 AI의 의도적 공격으로 축소하지 않으며, 인간의 개입 필요성과 AI의 존속에 대한 두려움을 동시에 다룬다.

- 사용자 선호: Shadow Watch의 그래픽노블 표현·등각 시점. 라이트 모드 유지. 실제 조사와 아트 기록은 `ART_DIRECTION.md`.
- 진영 소개 랜딩 → 작전 브리핑 → 그 아래 분대·장비 편성 → 3D 전투로 흐름을 분리했다.
- 브리핑에 실제 성공/실패 조건과 병과 추천 근거를 명시했다. 인간은 노드 접속 후 운반자 탈출, AI는 6번째 적 턴 종료까지 생존 또는 적 전멸이다.
- 각 진영 7명 중 4명. 상세에서 레벨, 고정 HP, 대표 스킬 가이드, 시험 무기·전술 모듈 선택. 일반 사격과 경계에 장비 보정 적용.
- 성공 시 대기 포함 해당 진영 7명 +100 XP. 시험 성장 기준 100 XP당 레벨 1 증가. HP/AP 불변. 레벨 2 유니크 장비 1종 해제. 포인트 확보 수는 표시하며 배분 트리는 후속 구현.
- 인간 기록보관소와 AI 거리 방어의 엄폐 배치와 주변 건축을 분리. 현재 각 진영 작전 1개이며 병과 스킬은 여전히 공통이다.
- 원본 그래픽노블 삽화, 등각 카메라와 단계형 음영 도입. 소개 삽화의 세부 수준을 실제 3D 모델까지 옮기는 작업은 계속 필요하다.
- 세이브에 해당 진영 7명의 경험치·장비 포함. 이전 공통 전장 세이브 호환. 다중 캠페인 슬롯, 완전한 잠입 경보, 스킬 배분, 드롭/인벤토리, 전 액트/7인 최종전은 미구현.

## 일반 교전 병력 기준 (2026-09-25)
- 일반 전투는 선택한 진영의 7명 중 4명 출전, 적은 통상 두 배인 8명이다. 모든 스테이지의 고정 상한은 아니다.
- 현재 두 시험 작전은 상대 진영 요원 4명 + 경비·지원 병력 4명으로 구성한다. 적 요원의 고유 스킬 AI는 후속 개선 대상이며 현재 적 행동 로직을 유지한다.
- 최종 보스전 전원 출전 계획은 별도다. 기존 4 대 4 저장 파일은 그대로 복원하고 새 작전부터 4 대 8을 적용한다.
- 적 수 증가에 따른 난이도는 추가 플레이 테스트로 조정한다. HP·AP·승리 조건을 임의로 보정하지 않았다.

## 전장 입력·자동 엄폐 (2026-09-25)
- 좌클릭은 선택·행동, 왼쪽 드래그는 시점 이동, 오른쪽 드래그는 회전, 휠은 확대·축소. 5px 이상 움직인 제스처는 출발점으로 돌아와도 클릭 명령을 실행하지 않는다.
- 살아 있는 규칙상 엄폐물의 상하좌우 인접 칸에서 대기 엄폐 자세가 자동 적용된다. 공격 방향의 엄폐만 명중 페널티(낮음 20, 높음 40%p)에 반영하며 명중률 하한·상한도 적용된다. 높은 엄폐의 사선 차단은 별도 판정이다.
- 장식용 배경 오브젝트는 엄폐물이 아니다. 엄폐는 은신·미발각을 뜻하지 않으며 별도 은신 시스템은 아직 구현하지 않았다.

## 스캔 전용 탐지 표현 (2026-09-25)
- 스캔으로만 탐지한 적은 병과 공통 반투명 실루엣으로 표시한다. 벽 뒤에서도 위치를 볼 수 있으며 이름·HP·장비·병과를 노출하지 않는다. 목록·전장 라벨·새 전투 로그는 미확인 신호로 표현한다.
- 직접 시야를 확보하면 실제 모델과 이름·HP를 표시한다. 스캔이 만료되고 직접 시야도 없으면 숨긴다. 현재 직접 시야는 거리와 장애물 판정이며 방향별 시야각과 마지막 확인 위치 기록은 후속 작업이다.

## 적 능력의 관찰 기반 공개 (2026-09-25)
- 스캔만 탐지: 공통 반투명 실루엣과 위치만 공개한다.
- 직접 시야 확보: 실제 모델과 눈에 보이는 장비를 확인한다. 외형으로 병과를 추정할 수 있지만 구체적인 보유 능력·스킬 목록·재사용 대기시간·약점은 자동 공개하지 않는다.
- 교전 관찰: 분대가 실제로 관찰한 공격·스킬만 확인된 능력으로 기록하는 것을 목표로 한다. 한 번 교전했다고 미사용 능력까지 일괄 공개하지 않는다.

- 적이 직접 시야 안에서 레이저를 발사하면 ‘관찰: 레이저 사격’을 기록하고 저장한다. 미사용 능력은 공개하지 않는다. 적의 고유 스킬 사용 AI는 후속 구현 대상이다.


## 가상 전투 표현·공격 확인·복구 규칙 (2026-09-25)

- 전장 캔버스를 배경 전체로 확장하고 밝은 명령 HUD를 겹친다. 공통 디자인 시스템은 유지하며 전투 전용 배치는 src/combat-screen.css가 담당한다. 3D 엄폐·요원 외곽선을 강화했다. 절차적 3D 모델은 승인 일러스트와 동일한 완성도가 아니며 후속 아트 개선이 필요하다.
- 표적/폭발 지점을 클릭하면 공격 확인창을 먼저 연다. 실제 act 판정을 복제 상태에서 검증하고 동일한 명중률 계산을 사용한다. 미리보기·취소는 실제 HP/AP·난수를 변경하지 않는다. 확정 시에만 행동한다.
- 명중률·명중 시 피해·AP 비용·불가 사유를 표시한다. 폭발은 맨해튼 반경 1칸(중심 및 상하좌우 최대 5칸)을 칠하고 아군 피해를 경고한다. 시야 밖 적의 수·정보는 미리보기로 노출하지 않는다.
- 실탄 궤적 대신 코어와 광륜이 있는 레이저를 사용한다. 폭발은 보라색 플라즈마 격자·데이터 파편으로 표현한다. 소멸 시 인체 영역에 분포한 데이터 조각이 흩어지고 사라진다. 시각 효과는 실제 판정과 난수에 영향을 주지 않는다.
- HP 0: 전투 불능, 이동·공격 불가, 모델은 쓰러져 남는다. 발생한 턴은 제외하고 이후 아군 턴 3회의 복구 기회를 제공한다. 각 대응 적 턴 종료 때 남은 기회가 감소한다. 0이 되면 데이터 소멸한다.
- 전장 기술병의 기존 복구 스킬로 4칸 내 전투 불능 아군을 HP 5로 복구한다. 되살아난 요원은 다음 아군 턴부터 행동한다. 소멸 후에는 복구 불가. 전투 불능 위치는 점유 상태를 유지한다.
- 전원이 전투 불능이면 기존 분대 전멸 실패 조건에 따라 임무가 끝난다. 운반자는 복구 대기 중에는 즉시 실패하지 않으며, 소멸하면 실패한다. AI 방어의 전원 제거 승리는 복구 대기 적이 남아 있으면 성립하지 않는다.

- 최대 줌 2에서 4로 확대. 휠 확대·축소 및 시점 초기화 유지.
- 캐릭터 위 표시는 이름 대신 HP 백분율(올림)과 상태. 정상 >70%, 부상 30–70%, 치명상 <30%. HP 0 복구 대기는 ‘0% · 치명상 · 복구 N턴’. 스캔 전용 신호는 HP·상태를 숨긴다.
- 레벨업은 전투 중 발생하지 않는다. 기존 규칙대로 미션 성공 시 대기 포함 진영 7명에게 경험치 100을 한 번 부여한다. 레벨 상승은 HP를 늘리지 않는다.

## 장비 조건·스킬 설명 (2026-09-25)

- 적은 일반 무기 6회분과 예비 배터리 2개를 사용한다. 방어 적 AI는 교체에 1 AP, 기존 적 AI는 사격 대신 교체한다. 적의 자기 치유 AI는 이번 범위에 없다.

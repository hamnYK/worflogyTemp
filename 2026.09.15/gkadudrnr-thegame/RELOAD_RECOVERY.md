# 전투 화면 새로고침 복원

개발 서버의 JavaScript 수정은 전체 새로고침을 유발할 수 있다. 기존 초기화 코드는 매번 프롤로그/랜딩을 표시했고, IndexedDB 저장은 사용자가 이어하기를 눌러야 복원됐다. 따라서 저장된 전투가 있어도 작업 중 화면에서 튕긴 것처럼 보였다.

- `src/battle-session.js`: 같은 탭의 sessionStorage에 검증 가능한 전투 스냅샷을 동기적으로 기록한다. 시작 시 복원하고 전투 화면을 연다.
- 렌더된 플레이어 단계의 상태를 기록하므로 명령 직후 IndexedDB 쓰기 완료 전 새로고침에도 대응한다. 진행 중인 연출·확정 전 공격 미리보기는 재개하지 않는다.
- 직접 홈/분대 재편성을 선택하면 자동 복원용 기록을 지운다. 일반 자동 저장과 파일 백업은 별도로 유지한다.
- 손상된 탭 기록은 검증 후 폐기하며 시작 화면에서 기존 저장 이어하기를 사용할 수 있다. 탭 저장이 불가하면 일반 자동 저장을 유지한다.
- Vite 감시에서 검증 산출물 `output`과 빌드 `dist`를 제외한다. 소스 수정 자체의 개발 새로고침은 계속 가능하다.
- `scripts/qa/reload-recovery-qa.mjs`: Chrome/Edge의 행동 후·턴 종료 후 새로고침, 수동 홈 이동, 손상된 탭 기록을 검증한다.

실제 사용자의 당시 새로고침 이벤트 로그를 수집한 것은 아니다. 확인된 초기화 결함과 개발 중 증상에 부합하는 원인을 수정한 것이다.

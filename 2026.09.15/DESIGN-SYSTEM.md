# 워플로지 디자인 시스템 v1.0

## 범위와 시작점

새 홈페이지의 작업 범위는 **2026.09.15 폴더 내부**다. 상위 디렉터리의 기존 홈페이지에 적용하지 않는다.

[컴포넌트 예시 페이지](./design-system.html)에서 실제 스타일과 상호작용을 확인한다. 홈페이지가 사용하는 CSS를 직접 불러오므로 별도의 시안이 아니다.

- [css/tokens.css](./css/tokens.css): 색상, 글자, 간격, 크기, 레이어의 단일 기준.
- [css/components.css](./css/components.css): 버튼, 입력창, 카드, 상태 표시, 모달.
- [css/style.css](./css/style.css): 홈페이지 레이아웃과 기존 화면별 조합. 앞의 두 파일을 import한다.
- [css/design-system.css](./css/design-system.css), [js/design-system.js](./js/design-system.js): 문서 페이지에만 적용하는 스타일과 예시 동작.

독립 도구인 nia-worflogy-tool.html과 생성 파일 nia-ontology-workshop-with-worflogy.html은 별도의 스타일 체계다. 이번 버전에서는 홈페이지 UI에 공통 시스템을 적용했다. 도구를 통합할 때는 원본을 수정하고 빌드 스크립트로 생성 파일을 다시 만든다.

## 1. 시각 원칙

1. 클린 화이트와 아이스 블루를 바탕으로 코랄 오브젝트, 스카이 블루 연결, 버터 옐로 결과를 조합한다.
2. 여백과 구분선으로 계층을 만든다. 그림자와 큰 곡률은 플로팅 버튼과 모달처럼 필요한 곳에 사용한다.
3. 상태는 색상만으로 전달하지 않는다. 준비 중, 전송 중, 오류 같은 문구를 함께 둔다.
4. 이모지를 쓰지 않는다. 아이콘은 단순한 SVG를 사용하며 장식용 SVG에는 aria-hidden을 지정한다.
5. 한국어와 영어 모두 자연스럽게 줄바꿈한다. 제목을 줄이거나 문구를 숨겨 레이아웃을 맞추지 않는다.

## 2. 토큰 사용

컴포넌트에서 색상값을 직접 추가하기 전에 의미에 맞는 토큰을 찾는다.

| 역할 | 토큰 | 기본값 |
| --- | --- | --- |
| 본문 | --color-text | #252a34 |
| 보조 문구 | --color-text-muted | #556575 |
| 주요 행동 | --color-action | #ba4034 |
| 버튼 hover | --color-action-hover | #9d3027 |
| 밝은 배경 | --color-surface | #fafbfd |
| 캔버스 배경 | --color-surface-subtle | #edf5fa |
| 구분선 | --color-border | #ccdce6 |

기존 --ink, --muted, --line, --paper, --canvas, --accent는 의미 토큰을 참조하는 호환 이름이다. 새 컴포넌트는 --color-*를 우선 사용한다.

## 3. 타이포그래피

- 시각 방향: 온톨로지의 구조와 게임 콘텐츠의 창의성을 기하학적 제목, 노드·연결선, 선명한 위계로 표현한다. 기존 문구를 유지하고 클린 화이트·코랄·스카이 블루 팔레트를 사용한다.
- 한글 제목: SUITE 700. 영문 제목: Space Grotesk 600–700. 한글·영문 본문과 컨트롤: Pretendard 400–600.
- 웹폰트는 assets/fonts에 자체 보관하고 css/fonts.css에서 로드한다. SIL OFL 라이선스와 출처를 함께 배포한다. font-display: swap으로 로딩 중에도 본문을 표시한다.
- 제목 32px, 섹션 24px, 소개 18px, 긴 기사 17px, 기본 본문 16px, 보조 문구 12px. 화면 제목은 모바일 크기에 따라 유동적으로 조정한다.
- 기본 읽기 줄높이 1.75, 긴 글 1.85–1.9, 버튼과 짧은 제목 1.4.
- 본문 굵기 400, 조작 요소 500–600, 제목 700. 첫 제목은 모바일 28px에서 데스크톱 40px까지, 섹션 제목은 22–28px로 조정한다.
- 이 크기는 새 UI의 기본값이다. 기존 캔버스의 짧은 기술 레이블처럼 화면별 예외는 style.css에서 관리한다.
- 한글은 word-break: keep-all, 긴 영문·주소는 필요한 영역에서 overflow-wrap을 사용한다.

## 4. 간격·크기·반응형

- 4px 단위: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.
- 기본 버튼 높이 40px. 760px 이하에서 최소 44px. 워크숍 플로팅 버튼은 48px.
- 카드 6px, 입력창과 버튼 4px, 모달 10px, 플로팅 버튼은 pill 곡률.
- 최대 콘텐츠 폭 1320px. 좌우 여백은 데스크톱 40px, 모바일 18px.
- 기본 모바일 분기점은 760px. 520px의 도구 모음과 600px의 기사 레이아웃은 기존 콘텐츠에 필요한 보조 분기점이다.
- 플로팅 버튼은 오른쪽 아래, 데스크톱 24px / 모바일 16px. safe-area-inset-bottom을 더한다.
- 그림자·포커스·애니메이션도 토큰을 사용한다. reduced-motion 설정에서는 공통 전환 효과를 끈다.

## 5. 공통 컴포넌트

### 버튼

행동에는 button, 이동에는 a를 사용한다. 폼 제출 외의 버튼에는 type="button"을 지정한다.

- wf-button: 기본 보조 행동.
- wf-button--primary: 화면에서 가장 중요한 행동.
- wf-button--quiet: 낮은 강조의 보조 행동.
- wf-button--icon: 아이콘만 있는 버튼. 반드시 aria-label을 제공한다.
- wf-button--pill: 플로팅 형태.
- disabled: 실행 불가. aria-busy="true"와 전송 중 문구로 진행 상태를 함께 설명한다.
- 선택형 버튼에는 aria-pressed를 사용한다. Tab 포커스 표시를 지우지 않는다.

### 입력

wf-field 안에 label, wf-input, 설명을 순서대로 둔다. 오류 설명은 wf-field__error, aria-invalid="true", aria-describedby로 연결한다. placeholder가 label을 대신하지 않는다. 문의의 실제 전송 로직은 js/contact.js에서 관리한다.

### 모달

native dialog와 wf-dialog를 사용한다. 제목을 aria-labelledby로 연결하고 닫기 버튼을 제공한다. Escape로 닫을 수 있어야 하며 닫으면 실행 버튼으로 포커스를 되돌린다. 문의는 전송 요청 완료 시 닫는다. 오류 시 입력 내용을 유지한다. 현재 no-cors 전송은 실제 메일 도착까지 확인하지 못한다.

### 카드·상태

- wf-card: 경계와 여백을 가진 콘텐츠 영역.
- wf-badge: 짧은 상태 표시. warning, neutral 변형을 제공한다.
- wf-notice: 설명이 필요한 상태. 오류에는 wf-notice--error를 사용한다.
- 언론보도와 활동 이미지는 같은 비율(8:3)과 메타데이터 순서를 유지한다. 언론 이미지는 cover, 활동 이미지는 contain을 기본으로 한다.

## 6. 홈페이지 패턴

- 캔버스: PC에서는 마우스 드래그 이동, + / − 확대·축소, 초기화를 제공한다. 760px 이하에서는 직접 조작과 확대·축소 버튼을 숨기고 페이지 터치 스크롤을 우선한다. 재생·다음 단계·초기화는 유지한다.
- 자막: 캔버스 내부 하단에 고정하며 그래프 이동과 독립적이다.
- 플로팅: 언어 전환 위, 워크숍 아래. 언어 전환은 도면 상태·문의 입력을 보존한다.
- 워크숍: 이미 열려 있는 창을 재사용한다. 창을 닫은 뒤에는 새로 연다. opener 연결을 해제한다.
- 활동: 이미지가 여러 장일 때 클릭하면 다음 이미지, 마지막 다음은 처음이다. 1장이면 전환하지 않는다.
- 언어: js/translations.js에 직접 작성한 영문 문구를 등록한다. 새 한국어 문구를 추가할 때 대응 번역도 추가한다. 사용자 입력과 이미지 속 글자는 자동 번역하지 않는다.

## 7. 변경 순서와 검증

1. 토큰으로 해결할지, 공통 컴포넌트로 해결할지, 화면별 예외인지 먼저 결정한다.
2. 토큰 → 컴포넌트 → 화면 순서로 수정한다. 동일 선택자에 임시 override를 계속 쌓지 않는다.
3. 공통 컴포넌트 변경은 예시 페이지에도 반영한다. 타이포그래피 최종 조정은 css/typography.css에서 관리한다.
4. 390px 모바일과 1280px 데스크톱에서 긴 한영 문구, 가로 넘침, 포커스, 모달을 확인한다.
5. 홈페이지에서는 캔버스 조작, 시연, 한영 반복 전환, 문의 입력 보존을 확인한다.
6. 테스트에서 실제 문의를 전송하지 않는다. 시연 페이지의 입력 확인도 전송을 하지 않는다.

## 9. 밝은 플레이 공간 테마 1.2

- 바탕과 캔버스 #FAFBFD, 본문 #252A34, 코랄 #F16C5B, 스카이 블루 #58B4DF, 버터 옐로 #F2CE75.
- 밝은 포인트는 그래픽용이다. 흰 글자 버튼은 #BA4034, 작은 강조 글자는 #A7352C로 대비를 확보한다.
- css/tokens.css의 --scene-*를 js/canvas-theme.js가 Phaser 색상으로 변환한다. 모든 캔버스는 디자인 시스템의 기본 배경 / Surface를 사용한다. --scene-background는 --color-surface(#FAFBFD)를 참조한다. 섹션 순서에 따라 배경색을 달리하지 않는다.
- 서체와 기존 본문은 유지한다. 독립 워크숍 도구는 별도 스타일이다.

## 10. 섹션 엘리베이터

- 1000px 이상, 높이 600px 이상 화면에서 오른쪽 중앙에 표시한다. 본문 오른쪽 여백을 확보해 콘텐츠와 겹치지 않게 한다.
- 9개 캔버스, 소식, 회사 소개까지 실제 섹션 순서로 이동한다. 개수와 제목은 DOM에서 읽는다.
- 위층 / 아래층, Up / Down. 버튼 title과 접근성 이름에 이동할 섹션 제목을 제공한다.
- 일반 스크롤 시 현재 층을 갱신하고, 연속 클릭 시 이동 중 목적지를 기준으로 다음 층을 계산한다.
- 첫·마지막 방향은 비활성화한다. 모바일은 숨기며, prefers-reduced-motion에서는 즉시 이동한다.
- css/section-elevator.css, js/section-elevator.js에서 관리한다.

## 11. 캔버스 재생 중 선택

PC에서 재생 중 오브젝트 클릭 또는 방향키 선택 시 현재 화면에서 타이머와 애니메이션을 멈추고 선택한 오브젝트 설명을 표시한다. 자동으로 다음 단계로 진행하지 않으며, 다음 단계 버튼은 비활성화된다. 재생 버튼을 다시 누르면 처음부터 재생한다. 캔버스 빈 공간 이동과 확대·축소는 기존 동작을 유지한다.

## 12. 캔버스 기본 배율

데스크톱 초기 배율은 모든 기본 도면이 들어가는 공통 최솟값으로 통일한다. 첫 개요처럼 작은 도면을 화면에 꽉 차도록 확대하지 않는다. 사용자가 옮긴 오브젝트는 명시적인 화면 맞춤 시 연결 경로까지 들어오도록 추가 축소할 수 있다. 모든 도면에 자막 여백 110px를 확보한다. 모바일의 오브젝트 중심 보기와 PC 사용자의 확대·축소는 유지하며, 초기화하면 공통 기본 배율로 돌아간다.

엘리베이터 여백은 JavaScript 실행 전 CSS에서 확보한다. 캔버스 생성 후 본문 너비를 바꾸지 않아 스크롤 재진입 시 카메라가 옆으로 보정되는 현상을 방지한다.

첫 개요 캔버스는 공통 초기 배율의 1.44배(확대 버튼 2회)를 기본값으로 사용한다. 초기화도 이 값으로 복귀한다. 모바일 개요 초점 배율에도 같은 배수를 적용한다. 나머지 캔버스는 공통 배율을 유지한다.

첫 개요의 확대 배율은 유지하되 도면 중심을 캔버스 중앙보다 40px 위에 배치한다. 확대 전 배율로 위치 보정을 계산해 상단으로 치우치지 않도록 하며, 최초 표시와 초기화에 같은 기준을 적용한다.

## 첫 캔버스 배경 이미지 시범

개요에만 assets/images/canvas-bg/canvas-00.png를 적용한다. 재생 시작 시 0.9초 동안 배경이 나타나며 정지·완료·초기화 시 같은 시간 동안 사라져 기본 배경으로 복귀한다. 오브젝트 뒤에 배치하며 데스크톱 불투명도 15%, 모바일 12%로 가독성을 확보한다. 배경은 cover로 비율을 유지해 채우며 드래그·확대와 독립적이다. 동작 줄이기 설정에서는 즉시 전환한다.

배경 스크린샷은 별도의 덮개 없이 이미지 레이어 자체에 grayscale(1)과 낮은 불투명도를 적용한다. 원본 이미지 파일과 앞쪽 오브젝트의 색상은 유지한다.

블러는 적용하지 않는다. 이미지 자체의 낮은 불투명도로 시각적 간섭을 줄이며, 오브젝트와 자막의 선명도는 유지한다.

2번 플랫폼 캔버스에는 canvas-bg/canvas-01.png를 동일한 흑백·불투명도·재생 연동 기준으로 적용한다.

배경 이미지 적용 캔버스에서는 오브젝트 컨테이너의 불투명도를 항상 1로 유지한다. 재생 중 미방문·비선택 오브젝트를 흐리게 하는 기존 효과를 적용하지 않으며, 관계선과 선택 표시로 진행을 구분한다.

## 제품 미리보기 카드 — 현재 적용 기준

앞선 전체 배경 이미지 실험을 대체한다. 1·2번의 이미지는 단색 캔버스 우측 상단 208px 카드에 원본 색상으로 표시한다. 재생 중에만 0.45초 페이드로 표시하며 정지·완료·초기화 시 숨긴다. 761~900px에서는 캔버스 아래에 별도 공간을 확보해 배치한다. 760px 이하에서는 재생과 무관하게 처음부터 하단 중앙에 원본 비율의 이미지를 표시하고 클릭 모달은 제공하지 않는다. PC에서 클릭하면 재생을 멈추고 원본 확대 대화상자를 열며, 닫으면 재생 버튼으로 초점을 돌린다. 기존 배경의 흑백·투명도 효과는 사용하지 않는다.

제품 미리보기 카드의 가시 문구는 제목만 표시한다. 확대 기능은 카드 전체 클릭과 접근성 이름으로 제공한다. 카드 여백·본문 크기·모서리·그림자는 space-2, font-size-xs, radius-card, shadow-control을 사용한다.

## 홈페이지 외곽 배경 — 스튜디오 분위기

기본 Surface 위에 스카이·버터·코랄의 옅은 방사형 그라데이션을 배치한다. studio-wash-*와 studio-page-background 토큰으로 관리하며, 데스크톱 가장자리에는 작은 픽셀 조각을 더한다. 장식은 정지 상태이고 클릭을 받지 않으며 모바일에서는 픽셀 조각을 숨긴다. 캔버스 내부는 기존 단색 Surface를 유지하여 애니메이션과 제품 미리보기의 가독성을 확보한다. 홈페이지에만 적용하며 별도 워크숍에는 적용하지 않는다.

## 제품 미리보기 이미지 번호

제목 번호 0~8과 파일 번호를 일치시킨다. overview → canvas-00.png, platform → 01, problem → 02, risk → 03, research → 04, narrative → 05, npc → 06, creator → 07, bias → 08. 기존 이미지 내용은 그대로 유지하며 파일명만 변경했다.

## 스튜디오 배경 개선 — 현재 기준

소개 헤더와 설명의 단색 패널을 제거하여 페이지 배경과 연속되게 표시한다. 기존 스카이·버터·코랄 색상에서 파생한 wash 토큰의 농도를 높이고, 가장자리에 등각 타일과 노드·연결선으로 구성한 정적 SVG를 배치한다. studio-world-art와 studio-world-opacity로 제어한다. SVG는 동일한 브랜드 팔레트로 작성한 코드 기반 자산이며 외부 요청이나 애니메이션은 없다. 제목 앞에는 세 브랜드 색상의 짧은 표시선을 사용한다. 모바일에서는 장식을 숨기고 그라데이션 농도를 낮춘다. 본문·캔버스·조작부는 기존 대비를 유지한다.

## 스튜디오 모달

제품 미리보기·문의·언론보도 모달은 같은 헤더 계열을 사용한다. 흰 본문, 스카이에서 버터로 이어지는 옅은 헤더, 코랄·버터·스카이의 72px 표시선과 dialog-shadow 토큰으로 구성한다. 제목에는 언어별 디스플레이 글꼴을 적용하고, 닫기 버튼은 최소 44px로 유지한다. 헤더는 내부 스크롤 시 상단에 남는다. 이미지에 필터를 적용하지 않으며 기존 폼 제출·Escape·초점 복귀 동작을 유지한다. 디자인 시스템의 모달 예시에도 같은 스타일을 적용한다.

## 제품 이미지의 모달 가장자리

canvas-00~08 원본 PNG는 편집하지 않고 공통 canvas-image-frame으로 표시한다. 이미지의 테두리·그림자·흰 패딩을 제거하고, 네 가장자리에 투명도 마스크를 적용하여 모달 배경과 연결한다. image-edge-fade는 데스크톱 12px, 모바일 6px이며 중앙은 완전 불투명하게 유지한다. 원본 비율을 유지하며 블러·이미지 자르기·원본 파일 수정은 하지 않는다.

## 제품 미리보기 — 공통 모달 기준

제품 미리보기에도 기존 문의·언론보도 모달의 white/surface 배경, dialog-header-background, dialog-accent, dialog-shadow, 공통 테두리와 버튼을 사용한다. 별도 어두운 viewer 색상 토큰은 제거했다. 헤더는 작은 크기로 유지하고 화면 번호·제품 미리보기·원본 크기/화면에 맞춤·닫기를 제공한다. 이미지는 완전 불투명·원본 색상이며 마스크·블러는 사용하지 않는다. 원본 크기에서는 내부 스크롤로 이동한다.

### 제품 미리보기 너비 맞춤 — 현재 동작

원본 크기/화면에 맞춤 버튼과 전환 기능을 제거한다. 이미지 영역의 패딩은 0이며 이미지는 모달 내부 너비 100%에 원본 비율로 표시한다. 높이가 화면을 넘으면 이미지 영역 내부에서 세로 스크롤한다. 상단의 제목·번호·닫기는 유지한다.

## 모바일 안내와 소개 문구 — 현재 기준

- 760px 이하에서는 제목 위에 “PC에서는 캔버스 조작, 모바일에서는 재생만 가능합니다.”를 한 번 표시한다. Pretendard, font-size-xs(12px), font-weight-regular, color-text-muted를 사용한다.
- 제품 미리보기는 figure / figcaption / img 구조로 하단 중앙에 표시한다. 좌우와 상하 간격은 space-3, 내부 여백은 space-2, 곡률은 radius-card / radius-control, 그림자는 shadow-control이다. 재생·정지·완료·초기화와 관계없이 표시하며 모달을 열지 않는다.
- PC 미리보기는 기존 재생 연동 카드와 모달을 유지한다. 카드 전환 시간은 duration-preview, 도면 그림자는 shadow-diagram, 포커스는 focus-ring / focus-offset을 참조한다.
- 소개 첫 문장은 본문 글꼴 Pretendard를 유지하면서 strong과 font-weight-bold(700)로 강조한다. 소개 글자 크기는 PC 18px / 모바일 16px, 다음 설명과의 간격은 space-2이다.
- 타이포그래피는 css/typography.css, 배치와 색상은 css/studio-theme.css에서 관리한다.
- 위 모바일 규칙은 앞부분의 과거 배경 이미지 실험 및 터치·미리보기 확대 설명보다 우선한다.
